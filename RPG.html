01

從指令到戰鬥結果

把角色準備、玩家選擇與行動執行，串成一套戰鬥流程。

  1. 01 / READY

    ATB 累積

    依速度累積行動條，滿條後通知戰鬥管理器。

  2. 02 / COMMAND

    指令選擇

    開啟攻擊或技能選擇，確認技能時檢查 MP。

  3. 03 / TARGET

    目標選取

    依技能條件篩選目標，確認後交回戰鬥流程。

  4. 04 / ACTION

    行動執行

    協調行動排隊、技能執行與戰鬥結果。

GAMEPLAY IMPLEMENTATION

玩家做出選擇，
系統接手執行。

指令選單與目標選取各自處理輸入，再由戰鬥管理器協調角色狀態，交給 BattleAction 執行攻擊、防禦與技能。

普通攻擊先保存目標並播放動畫；收到命中事件後，才進入傷害計算與套用流程。

02

讓戰鬥行為可被回看

從操作事件、角色行動到狀態區間，保留後續分析需要的資料。

將同一場戰鬥的 BOSS 行為、玩家輸入頻率、ATB 決策時間與角色狀態，放在一條時間軸上對照。

TXT 戰鬥總覽
整理戰鬥結果、輸入次數與角色行為統計，快速掌握一次測試。
CSV 事件明細
保留事件時間、角色、目標與行為，供後續資料整理與分析。
PNG 行為時間軸
將行動與狀態區間視覺化，對照不同角色在戰鬥中的變化。

戰鬥中收集紀錄，結束時匯出。

01ATB 累積與滿條事件

角色同時滿條，誰先準備？

實作方式依條件累積，排序後發出 Ready 事件

只有存活、未詠唱、未 Ready、未行動的角色會累積 ATB。速度經過 BattleCalculator 計算後，乘上每幀時間加入行動條。

同一幀滿條的角色先按敏捷排序，再以玩家優先與場上順序處理平手，最後逐一發出 ActorBecameReady 事件。

這裡區分「準備完成」與「執行行動」；滿條事件交由戰鬥管理器接續處理。

程式依據ATBSystem.cs

02指令選擇與合法目標

技能可以選擇哪些目標？

實作方式分開處理指令輸入與目標規則

BattleCommandController 在確認技能時檢查角色與 MP，再交給 BattleTargetController 進入目標選取。

隊友目標選取及技能目標解析使用 IsValidSkillTarget：Self 只能選施法者，復活技能要求目標已死亡，代受傷害技能則排除自己。

確認目標後，依待執行指令呼叫戰鬥管理器的攻擊或技能入口。

程式依據BattleCommandController / ActorQueryHelper

03行動佇列與失效行動處理

排隊角色死亡，如何處理？

實作方式執行前重新檢查，略過失效行動

每筆佇列資料保留角色與執行動作。取出時再以 CanRunQueuedAction 檢查角色是否存在且仍存活，略過失效項目。

玩家與敵人各有佇列；戰鬥管理器在沒有行動結算時，先嘗試玩家佇列，再嘗試敵人佇列。角色死亡時也會移除該角色的排隊行動。

Ready 名單與已提交行動的佇列分開維護，避免把滿條順序直接當作所有行動的執行順序。

程式依據BattleActionQueue / BattleManager

04普通攻擊動畫與命中結算

傷害如何銜接攻擊動畫？

實作方式先保存目標，在命中事件結算

ExecuteBasicAttack 先保存攻擊目標並呼叫角色播放動畫。角色的 OnAttackHitEvent 再經戰鬥管理器轉交 ResolveAttackHit。

命中入口會重新檢查目標，接著計算與套用傷害、清除待命中資料，再檢查勝敗並結束行動。

此片段說明普通攻擊的程式銜接；技能由自己的執行流程處理。

程式依據Actor / BattleManager / BattleAction

05戰鬥紀錄的生命週期與匯出

如何保留一場戰鬥的操作？

實作方式戰鬥中收集事件，結束時統一匯出

UI 在有效操作入口記錄選單移動、確認與取消；Session 另外收集 ATB 決策、角色行動與狀態區間。

勝利、失敗或正常中斷時，由管理器完成 Session 並交給 Exporter。IsCompleted 防止重複完成；Exporter 在 Windows 環境輸出 TXT、CSV 與 PNG。

紀錄區分「輸入」與「行為」。攻擊、防禦、技能被接受時結束 ATB 決策區間；道具與逃跑則記為嘗試。

程式依據BattleTelemetrySession / BattleTelemetryExporter
